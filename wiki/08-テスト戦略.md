# 🧪 08. テスト戦略

## 8.1 現状

- 自動テスト（unit/integration/e2e）は未整備
- 実運用は手動スモークテスト中心
- デバッグ時は `x-ask-debug: 1` を活用

(参照: `../apps/review-page/app/api/review-ask/route.ts:1493-1528`)

## 8.2 最低限の手動テスト項目

| 区分 | テスト | 期待結果 |
|---|---|---|
| 投稿 | `/course_reviews` で必須項目のみ入力し送信 | `course_reviews` 登録、`embedding_jobs` queued |
| 投稿 | タグ5個以内・12文字以内 | `review_tags`, `course_review_tags` 登録 |
| チャット | `#高難易度` 送信 | `search_subjects_by_tags` が呼ばれる |
| チャット | 科目名のみ質問（大学名省略） | 所属大学補完で検索 |
| チャット | おすすめ授業→「その1つ目」 | 文脈解決で科目詳細へ遷移 |
| バッチ | embeddings/rollups API 実行 | counts が増加、dirty が解消 |

## 8.3 回帰テスト観点（今回実装に重要）

- フォーム必須条件
  - 教員名は必須
  - 受講年度・学期・単位数は任意
  - 成績・評価（難易度/課題難易度/出席/おすすめ）は必須
- ハッシュタグ検索
  - 全角`＃`と半角`#`の混在
  - 大学名省略時の所属補完
  - 上限件数（5件）
- Webhook経路
  - ハッシュタグ時に `ASK_REVIEW_API_URL` を優先
  - エラー時のフォールバック文言

(参照: `../apps/review-page/app/course_reviews/page.tsx:478-509`、`../apps/review-page/app/api/review-ask/route.ts:744-759`、`../apps/line-ai-bot/api/webhook.js:490-527`)

## 8.4 推奨する自動テスト追加

1. `review-ask` の tool schema 検証（required/propertiesの不整合防止）
2. `search_subjects_by_tags` の集計ロジック検証（AND条件・大学補完・review_count閾値）
3. `course-reviews` 投稿APIのバリデーション検証
4. webhook 分岐の単体テスト（hashtag / review / company / casual）

## 8.7 実行上の注意

このリポジトリでは、依存インストール前は `next lint` / `next build` を実行できません。
提出直前は各アプリで `npm install` 後にビルド検証してください。

- `apps/review-page`: `npm run build`
- `apps/subject-browser`: `npm run build`
- `apps/line-ai-bot`: `node api/webhook.js`（起動確認）
